# Root Cause Analysis

## Purpose

Root Cause Analysis (RCA) documents what happened, why it happened, how it was resolved, and how recurrence will be prevented.

---

## Incident Summary

Provide a concise description of the incident.

---

## Customer Impact

Document:

- Who was affected
- What functionality was affected
- Duration
- Business impact

## Symptoms

Describe the observable symptoms.

---

## Root Cause

Document the confirmed technical root cause.

Do not confuse the customer-facing symptom with the underlying cause.

---

## Contributing Factors

Examples:

- Missing monitoring
- Configuration issue
- Insufficient testing
- Dependency failure
- Capacity limitation

---

## Resolution

Describe the remediation that restored service.

---

## Validation

Explain how the team confirmed that the issue was resolved.

---

## Preventive Actions

- Improve monitoring
- Add automated tests
- Improve alerting
- Update documentation
- Improve deployment process
- Improve capacity planning

---

## Lessons Learned

Document what the team learned and what should change going forward.
